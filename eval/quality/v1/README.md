# Quality Observation schema v1

`quality-observation.schema.json` describes the whole-reading report emitted by
`ime-eval quality-score`. It is separate from the semantic Judge schemas:
expected surfaces and segment contracts belong only to this deterministic
lane. `quality-capture.schema.json` describes both capture lanes.

The report is restricted to `capture_lane=whole_reading_core`. It records the
core evaluator/dictionary/git identity, the exact `quality-stage1-default`
options identity, the production candidate limit (18), each case's
`assertion_scope`, surface Top-1/Top-18 rank, mean reciprocal rank (MRR),
segment sequence observations, negative controls, and
terminal/truncated/elapsed capture metadata. Candidate origin is recorded only
when the stable core API exposes a system-entry ordinal; otherwise it is
explicitly `null` (`unsupported`). Cost and segment sequence are recorded when
provided by the core API.

`quality-capture` is a diagnostic-only replay of the real engine's active
segment candidate UI. Its `active_segment_replay` lane is intentionally not
accepted by `quality-score`; passing it to the scorer fails closed because
active-segment candidates are not whole-reading Top-18 candidates.

`quality-core-capture` is the Stage 1 main lane. It invokes the existing
`sakura-core::Converter` once per full reading with learning, user dictionary,
reranker, and input repair disabled, and records at most 18 full-reading
candidates plus their available segment sequence.

The determinism fingerprint includes only stable candidate/result material and
artifact/options identity. Score elapsed time and per-case elapsed,
terminal, and truncated metadata are deliberately excluded; changing a
candidate, rank, segment, origin, or cost changes the fingerprint.

The supplied `before_surface` is retained under each observation's
`competitors` field. Fixture-declared negative controls have their own
captured candidate list and are reported under each system's
`negative_controls` field; they are not counted as ordinary before-surface
competitors.

`fixture.schema.json` describes the Stage 1 challenge fixture under
`eval/corpus/behavioral/conversion-quality-stage1/fixture.json`.

The checked-in Stage 1 baseline is generated by `quality-score` from a
`whole_reading_core` capture and conforms to this report schema. It is an
observational reference only (`observational_not_release_gate`); it is not a
semantic gold set or a release acceptance threshold. Surface Top-1, Recall@18,
and segment-exact values are measurements of the identified artifact/config,
not unconditional product requirements.
