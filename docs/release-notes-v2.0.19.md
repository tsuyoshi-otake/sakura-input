# Sakura Input 2.0.19

このリリースは、日本語変換で誤った候補が先頭に出ていた問題の修正です（#371、#372）。

- よく使う言い回しで、誤った候補が先頭に出ていたものを直しました（#371）。
  - 「しつれいのないように」「ごかいのないように」が「失礼の内容に」「誤解の内容に」になっていたのを、「失礼のないように」「誤解のないように」が先頭になるようにしました。「メールの内容に誤りが」のような「の内容に」の変換は変わりません。
  - 「せいどがたかい」など、「精度」のあとに「が」「も」「の」と「高い」「低い」が続く場合は「精度」が先頭になります。「せいど」単独や「制度を変える」などは、これまでどおり「制度」が先頭です。
  - 「けいせいがぎゃくてん」は「形勢が逆転」が先頭になります。「形成する」などは変わりません。
  - 「なりきん」で「成金」が出るようにしました（これまでは「成り金」だけでした）。
  - 「まるまる」は「丸々」が先頭になり、「〇〇」は3番目になりました。「〇〇さん」の変換は変わりません。
- 短い読みが、助詞と「書い」「似合い」のような動詞の途中の形に分かれて変換されることを減らしました（#372）。たとえば「にかい」は「二階」、「にまい」は「二枚」、「にあい」は「似合い」、「におい」は「匂い」が先頭になります。動詞の途中の形（「書い」など、あとに「た」「て」が続く形）が入力の最後に来る区切り方を、変換で選ばれにくくしました。うしろに読みが続く文節を区切り直して変換する場合は、これまでどおりこの形を候補にします。「にしゅうかん」が「に習慣」になる問題は、このリリースでは直っていません。
- 開発用の評価ツール（neural-eval）が、製品と同じリランカーの選び方で精度を測るようにしました（#370）。変換の動作は変わりません。

2.0.18までに学習した内容と設定は、そのまま使われます。学習で誤った候補が先頭に固定されている読みは、学習の内容がこの修正より優先されます。

検証は、各項目のテスト（修正前のコードで失敗することを含む）、変換精度のゲート（追加した例文を含む1,520件）、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
