# Sakura Input 2.0.24

このリリースは、診断ログが満杯になると新しい記録が止まる問題を直したものです（#313、#406）。入力や変換の結果は変わりません。

- 切断ログ（`ipc-disconnects.bin`）が、満杯になっても新しい出来事を記録し続けるようにしました（#313）。
  - これまでは 1 MiB に達すると、それ以降の出来事は記録されず、エラーも表に出ませんでした。満杯になった後に起きた切断は、理由が読めませんでした。
  - ファイルの大きさは 1 MiB のまま、32,767 件の枠に新しい出来事を書き、いちばん古いものから上書きします。
  - キー入力の経路では、待つことも再試行することもしません。別のプロセスが書き込み中のときや書き込みに失敗したときは、その出来事を捨てます。捨てた件数はプロセスごとにメモリ上で数えておき、同じプロセスの次の書き込みが成功したときに記録します。その前にプロセスが終了した場合や、書き込みが失敗し続けた場合の分は件数に入らないため、表示される破棄の件数は実際より少ないことがあります。
  - 以前のビルドが書いた追記型のログは、そのまま読めます。次の出来事を記録するときに、新しい形式へ変換します。満杯だったログは、いちばん古い 1 件だけを失います。
  - エンジンとの接続をリセットした出来事（`cancelled-state-terminalized`）に、きっかけを記録します。「文脈の置き換え」「ホストによる編集セッションの拒否（拒否の種類つき）」「その他」の3つに分け、入力した文字、文書の内容、ホストのエラー文は記録しません。
  - `sakura_settings.exe diagnostics show` に、きっかけの内訳と、記録・上書き・破棄の件数を表示します（破棄の件数は、上に書いた範囲で数えられたものです）。
- 開発者向けのデバッグトレース（`logs\debug.tsv`）が、満杯になっても新しい行を記録し続けるようにしました（#406）。
  - これまでは 2 MiB に達すると、それ以降の行は記録されず、キーを処理するたびにファイルを開いて大きさを確かめるだけになっていました。開発者モードで普段どおり使うと、数時間で満杯になっていました。
  - `debug.tsv`（現在）と `debug.1.tsv`（ひとつ前）の2世代にし、直近の約 1〜2 MiB を常に残します。1 MiB を超えている旧版の `debug.tsv` は、そのままひとつ前の世代になります。
  - 書き込みに失敗したときは、100 ミリ秒から最大 60 秒まで間隔を空け、その間はファイルに触れません。
  - `sakura_settings.exe diagnostics debug` は2世代をまとめて表示し、`diagnostics clear` は両方を消します。

2.0.23までに学習した内容と設定は、そのまま使われます。

検証は、切断ログとデバッグトレースの単体テスト（修正前のコードで失敗することを含む。複数のスレッドとプロセスからの同時書き込みを含む）、診断コマンドの表示のテスト、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
