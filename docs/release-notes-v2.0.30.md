# Sakura Input 2.0.30

読み全体に一致するユーザー辞書の登録語を、システム辞書の語と同じく「辞書がすでにこの読みに答えている」ものとして扱うようにしました。これまでは、システム辞書の語なら効く順位の保護が登録語には効かず、推測で作った候補が登録語より前に出ることがありました（#446）。

- 読み全体に一致する登録語があるとき、動詞の語幹に日付（八日 など）を付けて作った候補は、登録語より後ろに並びます。候補からは消えません。
- 読み全体に一致する登録語があるとき、読みを直して作った候補（濁点の付け外しなど）と、コストの高い細切れの組み合わせの候補を出しません。システム辞書の語が読み全体に一致するときと同じ扱いで、条件も同じです（登録語の表記が2文字以上の漢字だけ、またはカタカナ・英数字だけで、読みが6文字以下か分割できない語のとき）。
- 打った読みの一部がユーザー辞書の登録語の読みと一致するとき、その部分の読みを直した候補は、システム辞書の語と一致するときと同じだけ後ろに下がります。
- 英字と数字を両方含む識別子（例：esp32）を Shift で入力したとき、システム辞書の語がどれだけ多い読みでも、同じ読みの登録語が候補から消えないようにしました。いまの辞書には、これに当たる読みはありません。

登録語のない読みの変換は変わりません。予測候補の並びも変わりません（読み全体に一致する登録語は、これまでも予測でシステム辞書の語より上に出ていました）。登録語のコストは変えていないので、変換で登録語が先頭に出ることは保証しません。

それぞれの変更について、修正前のコードで失敗するテストを用意しました。一般の日本語変換の精度ゲート（`accuracy-gate --check`）は合格で、結果は 2.0.29 から変わっていません。精度ゲートのコーパスはユーザー辞書を使わないためです。インストールした状態での画面の確認はしていません。

既存の設定・学習・履歴・ユーザー辞書の形式はそのまま使用できます。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
