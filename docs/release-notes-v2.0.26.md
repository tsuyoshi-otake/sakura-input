# Sakura Input 2.0.26

このリリースは、一部の一般的な言葉の説明に特定の製品の意味だけが出ていた問題を直し、2.0.25 で長くなった辞書を開く時間を短くし、エンジンの終了や再起動がまれに止まる問題を直したものです（#429、#427、#422）。

- 辞書の説明を直しました（#429）。
  - これまでは、プロジェクトで確認して書いた説明があっても、取り込んだ用語集や日本語 WordNet の説明があると、そちらが表示されていました。今後は、同じ辞書エントリについては、確認済みの説明を表示します。取り込んだ説明についていた関連語も、確認済みの説明では表示しません。
  - 用語集の 1 つの製品での意味だけが出ていた一般的な言葉 16 件に、一般的な意味を先に、製品での意味を後に書いた説明を付けました。たとえば「リポジトリ」は DDD の設計パターンとしての説明から、「ソースコードなどを変更履歴とともに保存・管理する場所」という説明になります。ほかに Channel、Cluster、Room、scratch、アプライ、データソース、ビュー、プラン、プロファイル、ポータル、ライフタイム、ワークメモリです。
  - 「過程」に説明を付け、「対象」の説明を日本語 WordNet の直訳調の文から書き直しました。「腹をくくる」も、確認済みの説明が表示されるようになります。
  - 説明が変わったのはこの 19 件だけです。候補の追加や削除、順位、コスト、接続の情報は変えていません。説明のある辞書エントリは 269,339 件から 269,340 件になりました。
  - Hook、Selector、Deployment、Strict Mode、Pod のように、製品での意味のほうがよく使われる言葉の説明は変えていません。
- エンジンが辞書を開く時間を短くしました（#427）。
  - 辞書を開くときの検査で、多くのエントリが共有している同じ説明文を、参照のたびに検査していました。説明文の表は 1 回だけ検査するようにしました。検査の内容と、壊れた辞書を開くときに拒否することは変わりません。
  - 2.0.25 の辞書を開く時間の中央値は、リリース前の測定で 65.3 ミリ秒から 42.4 ミリ秒になりました。2.0.24 の辞書との差は、約 22 ミリ秒から約 3 ミリ秒になります。キー入力ごとの変換にかかる時間は変わっていません。
- エンジンの終了や再起動が、まれに止まったままになる問題を直しました（#422）。
  - 予測の処理を止めるときの通知が、処理側が待ちに入る直前に届くと失われ、エンジンが予測の処理の終了を待ち続けることがありました。通知の書き込みを、処理側が待つときと同じロックの中で行うようにしました。

2.0.25までに学習した内容と設定は、そのまま使われます。

検証は、確認済みの説明が取り込んだ説明より優先されることの単体テスト（修正前の処理で失敗することを含む）、確認済みの説明がすべてビルドした辞書に入っていることのゲート（2.0.25 の辞書では 19 件の不一致を検出）、新旧の辞書の比較（エントリは一致し、説明の違いは 19 件だけ）、辞書を 2 回ビルドして結果が一致することの確認、説明文の表を壊した 11,000 通り以上の辞書イメージで修正前と同じ判定になることのテスト、辞書を開く時間の新旧の比較、予測の処理を止めるときのロックのテスト、負荷をかけた状態でのテストの繰り返し、辞書を使う 6 つのゲート、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
