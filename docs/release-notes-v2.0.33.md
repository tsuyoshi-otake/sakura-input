# Sakura Input 2.0.33

今回は、インストール済み 2.0.32 の開発者ログ調査で見つかった4件への対応です。変換の1行目が実際の観測どおりに正しくなり、原因調査用の記録も強化しました（#457、#465、#466、#467）。

## 変換の1行目の誤りを修正（#467）

開発者ログで観測された、1行目が誤る変換12件を修正しました。原因は3種類あり、それぞれに対応しています。

- 直前の確定とまたぐ合成候補の再評価が、途中で途切れるつぎはぎの候補を1行目に上げてしまう設計上の隙間を修正しました（例: 確定の直後の変換で、存在しないつぎはぎが本来の表記を上回ることがありました）。本来の設計意図である「確定境界をまたぐ一語」の評価は維持しています。
- 助詞・助動詞のまとまり（機能語）は、読みと同じ表記（ひらがな）が正解になるため、読み飛ばし規則の対象から外しました。`ばかり` などは1行目にひらがなが出ます。
- 辞書の価格と語の欠落を修正しました。観測された読みについて、接続コスト込みで誤った候補を下回り、既存のコーパス頻度と同じ価格帯に収まる値を設定しています。`かぜ` は `風邪` と `風` が同じ接続クラスを持つため、単体の価格では区別できず、`かぜひいて` を句として登録する方法で対応しました。

いずれも accuracy-gate の回帰コーパスに読みと期待表記を追加し、壊れる行がないことを確認しています。

## キー処理の所要時間を履歴に記録する診断（#457）

キーの処理が遅い要求について、エンジン側が「どの段階で時間がかかったか」を開発者入力履歴に記録するようになりました。記録されるのは、要求の待ち時間・準備・処理・応答書き込み・合計の5つの所要時間（マイクロ秒の数値）だけで、入力内容は一切含まれません。記録は、履歴が有効でセッションが確立し、かつスコープが記録を許可する場合にのみ行われます。

この診断は、まれに発生するキー応答の遅延と未確定文字の消失の原因を特定するためのもので、原因そのものは次の観測で調査します。

## 確定の経路を履歴に記録（#465）

確定の記録に「どの経路で確定したか」を表す値を追加しました。キー入力による確定・確定要求・候補選択による確定・IMEモード変更による確定などが区別できます。これは、確定キーが押されていないのに確定が記録された稀なケースの原因を特定するための診断で、原因そのものは次の観測で調査します。

履歴の形式はバージョン3になりました。過去の履歴ファイル（形式2）はそのまま読み込めます。

## サインイン時の修復失敗にエラーコードを記録（#466）

サインイン時に実行される入力方式プロファイルの修復が失敗したとき、`logon.status` に失敗のエラーコードが残るようになりました。以前は `profile_repair=failed` とだけ記録され、失敗の理由をあとから調べることができませんでした。

設定・学習・ユーザー辞書の形式に変更はありません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
