# Sakura Input 2.0.25

このリリースは、辞書の説明を大きく増やし、キーへの応答が少し遅れても変換を捨てないようにし、履歴の消去がまれに失敗する問題を直したものです（#412、#415、#417）。

- 辞書の説明を増やしました（#412）。説明のある辞書エントリは 31,301 件から 269,339 件になりました（全体 661,428 件のうち、4.73% から 40.72%）。
  - 活用した形にも、基本形の説明を引き継ぎます。引き継ぐのは、基本形が読みと表記で一つに決まり、その基本形に説明があるときだけです。すでに説明のある活用形は、そのままにします。
  - 引き継いだ説明は「『基本形』の活用形。基本形の意味：…」の形で、活用形であることと、書いてあるのが基本形の意味であることを示します。否定形や仮定形でも、肯定の意味を言い切ることはありません。
  - 引き継ぎは、Sakura Input が活用形から作る候補（151,104 件）と、Mozc の辞書にもともとある活用形（75,606 件）の両方に使います。
  - 既存の動詞・形容詞の基本形に 11,294 件、記号に 34 件の説明を書き足しました。
  - 足したのは説明の文字列だけです。候補の追加や削除、順位、コスト、接続の情報は変えていません。辞書ファイル（`system.dic`）は、38.8 MB から 46.6 MB になります。
- キーを押してからエンジンの応答を待つ時間を、最大 200 ミリ秒にしました（#415）。
  - これまでは、応答が 50 ミリ秒を超えて遅れると、変換中の文字を確定し、エンジン側の変換の状態も捨てていました。エンジンがそのキーを処理したあとでも、遅れて届いた応答は使われませんでした。
  - 2 回続けて間に合わなかったときは、エンジンが応答するまで 50 ミリ秒の待ちに戻します。エンジンが固まったときに、入力先のアプリの画面が長く止まらないようにするためです。応答が届けば 200 ミリ秒の待ちに戻ります。
  - 200 ミリ秒を超えて遅れたときは、これまでどおり変換中の文字を確定して復旧します。
  - エンジンが止まっているときの動作（2 秒おきの再接続）と、キー入力の最中に再接続する待ち時間（50 ミリ秒）は変えていません。
- 開発者向けの入力履歴を切った直後に履歴を消すと、まれに失敗する問題を直しました（#417）。
  - 履歴の書き込みが止まり終わる前に消去が始まり、履歴ファイルの排他ロックに当たって、内部エラー（`Internal`）になっていました。`sakura_settings.exe diagnostics clear` でも同じ順番で起きえました。
  - 消去は、履歴の開始と停止が落ち着くまで最大 1.2 秒待ってから実行します。待ち切れなかったときは、内部エラーではなく「混み合っている」（`Busy`）を返します。

2.0.24までに学習した内容と設定は、そのまま使われます。

検証は、活用形への説明の引き継ぎ規則の単体テスト（基本形が一つに決まらない場合、基本形が変化した場合、基本形に説明がない場合を含む）、引き継ぎレポートの検証スクリプトのテスト、辞書を 2 回ビルドして結果が一致することの確認、新旧の辞書イメージの比較（説明に関する 5 つのテーブル以外は一致）、辞書を使う 5 つのゲート、キー応答の待ち時間と履歴消去のテスト（修正前のコードで失敗することを含む）、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
