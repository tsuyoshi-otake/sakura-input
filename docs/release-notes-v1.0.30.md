# Sakura Input 1.0.30

診断のためのリリースです。**入力の挙動は 1.0.29 から変えていません。** 変換直後に全角スペースが入る不具合（#102）は 1.0.29 で被害を止めましたが、なぜキー送信が 50 ms 予算を超えるのかは未解明のままです。原因を絞り込むための計器を製品に入れます。

## 主な変更

### engine セッションが破棄された理由を記録します（#102）

1.0.29 の修正は、engine セッションが破棄されたときに Space 1 回を吸収して被害を止めるものでした。しかし「どの経路で破棄されたのか」を製品側は 1 バイトも残していませんでした。TSF 側でセッションを捨てる経路は 21 あり、すべてが引数のない同じ呼び出しを共有していたためです。

21 経路すべてに名前を付け、理由を必須の引数にしました。任意の注釈ではなく必須にしてあるので、今後新しい破棄経路を足すときは名前を決めない限りビルドが通りません。

件数は既存のタイムアウト記録の隣に、上限 1 MiB の別ログとして残ります。設定画面と `sakura_settings.exe diagnostics show` は 2 つの表を**別々に**表示し、合算しません。セッション破棄の大半はホスト側のライフサイクルに対する正しい応答であり、タイムアウトに足すと不具合の件数として読まれてしまうためです。件数が 0 の理由も省略せず印字します。「一度も起きていない」と「数えていない」は別の答えだからです。

### 接続を拒否した理由を記録します（#104）

engine への接続を検証して拒否したとき、記録は「信頼できないサーバー」だけで、5 つある検査のどれが拒否したのかが分かりませんでした。5 つの検査はいずれも同じ Windows エラーになりえたうえ、そのうち 2 つは自分でそのエラーを組み立てていたため、エラーコードを通しても検査を特定できませんでした。

拒否した検査そのものを記録するようにしました。「別のプログラムがパイプを提供していた」と「何が提供しているのか確認できなかった」は意味が異なり、セキュリティ上の問題は前者だけです。

あわせて、renderer が自分自身の実行ファイルの場所を解決できなかった場合に「信頼できないサーバー プロセス 0」と報告していた 2 箇所を直しました。どちらもサーバーを検証する前段での失敗であり、サーバーには何も尋ねていません。

接続を拒否する条件そのものは変えていません。従来どおり、検証に失敗した接続はすべて拒否され、ハンドルは Hello を送る前に破棄されます。

## 含まれないもの

- **入力の挙動は変わりません。** 変換、候補、キー操作、辞書は 1.0.29 と同一です。このリリースは記録を増やすだけで、不具合の修正を含みません。
- **50 ms のキー予算を超える原因は未解明のままです。** 今回入れたのは原因を絞るための計器であって、超える頻度を下げる変更ではありません。
- 有力な候補として #107 を起票しています。45.4 MiB の辞書ファイルマッピングが Windows にワーキングセットから削られ、入力を再開したときの再フォールトが停止を起こしている、という仮説です。稼働中のプロセスでワーキングセットが最大値から 31.8 MB 削られていること、稼働 1 時間未満で 666,548 回のページフォールトが起きていること、待機中はフォールトが 0 であることは実測しました。ただし**そのうち実ディスク読み込みの割合は未測定であり、原因とは確定していません。**
- タイムアウトの記録は「予算を超えた事実」だけを持ち、**超過量を持ちません**。51 ms と 1800 ms が同じ 1 件として残ります。
- `verification/space-key-dispatch/traceability.json` の判定は、以降変更された TLA+ 仕様と要件に対して計算されたもので、現在のコードについては何も述べていません（#106）。
- 候補数上限の設計（読み長による clamp と遅延 N-best 展開のどちらを採るか）は #100 / #103 で継続審議中です。このリリースは 1.0.29 と同じ読み長 clamp を採っています。
- **Sakura Pad の GitHub 同期は未実装です。** 下部バーの同期ボタンは「GitHub 未設定」と表示するだけで、通信は行いません。メモは端末内にとどまります。
- Pad の dark テーマと Windows ハイコントラストは、自動検証だけで実画面確認が済んでいません。
- Pad 一覧の検索はタイトルと本文の部分一致ですが、英字の大文字小文字を無視するだけで、全角・半角やひらがな・カタカナの正規化は行いません。

## 検証

- workspace 全体の format、Clippy（`-D warnings`）、`cargo test --workspace` に成功しました。
- 2 つの診断ログは記録の形式を共有しており、片方だけ形式が変わることがないようにしてあります。一方で、種別を分けているのは先頭 4 バイトの識別子だけで、記録の種別コード 1〜10 は**両方のログで有効な値**です。片方のログをもう片方として読んでも 1 件も計上されないことを、両方向で固定するテストを入れています。
- 診断の書き込み先はテスト時にシステムの一時領域へ切り替わります。切り替えを忘れると、テストの実行が利用者の診断記録へ追記され、これから測ろうとしている数値そのものを汚すためです。

## 対応環境

Windows 11 build 22000 以降、x64、AVX 対応 CPU。32 bit ホスト用 DLL と ARM64 ネイティブ版は含みません。

## インストール前の確認

この Release は owner 承認済みの Authenticode 未署名版です。GitHub Release の `sakura_setup.exe` を取得し、同じ Release にある `release-manifest.txt` の SHA-256 と PowerShell の `(Get-FileHash .\sakura_setup.exe -Algorithm SHA256).Hash` が一致することを確認してから手動で実行してください。

未署名 installer は自動更新の Authenticode 検証を通らないため、自動取得・実行されません。updater の fail-closed 動作は維持されます。

アップグレードは versioned payload の side-by-side 切替で行われます。新しい payload の検証に失敗した場合は、TSF 登録を新しい版へ切り替えずに中止します。
