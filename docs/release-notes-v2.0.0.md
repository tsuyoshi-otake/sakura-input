# Sakura Input 2.0.0

内部構造を大きく組み替えたアーキテクチャ再編を含む、最初のメジャーリリースです。**再編はまだ途中です**（計画の Phase 0–7 のうち、変換エンジンの分割 Phase 3.1 まで）。変換結果や操作方法を変えることが目的のリリースではありません。利用者に見える修正は、1.0.39 で更新確認が失敗し続けていた問題の解消です。

## 主な変更

- **更新確認の失敗を修正しました（#150）。** 1.0.39 では、手動インストールを続けていた環境で `更新情報の検証に失敗しました: update trust state is below the embedded trust floor` が毎回表示され、回復手段がありませんでした。現在の実行ファイルでは使えない古い記録は「記録なし」として扱い、署名検証済みの更新情報から書き直します。巻き戻し攻撃を防ぐ下限は実行ファイルに埋め込まれたままで、弱めていません。記録ファイルが壊れている場合のエラーには、そのファイルのフルパスを表示します。
- **内部構造の再編（Phase 0–3.1）。** 変換処理、学習・履歴の保存、候補の再順位付け用プロトコル、設定の保存を、責務ごとの小さなcrateへ分けました。依存方向の規則とテスト構成の検査をCIで強制しています。
- 変換エンジンの分割（Phase 3.1）では、固定した評価コーパスで分割前後の変換結果がビット単位で同一であることを確認しました。
- 候補ポップアップの表示（ダーク／ハイコントラストの配色、詳細ペインの幅、キャレット追従）を実画面で検査する自動テストを直しました。候補の配置処理そのものは変えていません。
- サンドボックス（AppContainer）内のengineを検査する際、実行ファイルの識別を厳密に照合するようにしました。通常のインストール時の動作は変わりません。

## 検証と残る課題

format、Clippy、workspaceテスト、Releaseビルド、installer生成を確認してリリースします。辞書入力は1.0.39から変更していません。engineとTSF DLLの間のプロトコル版は22のままです。

アーキテクチャ再編は、Phase 1 の一部（1.10、1.11）、Phase 3.2 以降、Phase 4–7 が残っています。高負荷時に文字が失われる問題（#148）と、VS Codeで入力中に落ちる問題は、このリリースでも解消していません。ダーク表示とWindowsハイコントラストでの候補ポップアップの目視確認（#168）も残っています。

## 導入方法

このReleaseはowner承認済みのAuthenticode未署名版です。Windowsには「不明な発行元」と表示されます。GitHub Releaseから取得した `sakura_setup.exe` のSHA-256を `release-manifest-v2.txt` と照合して、手動インストールしてください。Sakura固有のmanifest署名は、Windowsのコード署名とは異なります。未署名版は自動更新で取得・実行されません。

## 対応環境

Windows 11 build 22000以降、x64、AVX対応CPU。32 bitホスト用DLLとARM64ネイティブ版は含みません。
