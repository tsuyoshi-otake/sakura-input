# Sakura Input 1.0.23

「たて」で「縦」が候補に出ない問題を、単語固有の追加ではなく、辞書候補の上限を表示表記単位で扱う共通規則によって修正するリリースです。

## 主な変更

- Mozc辞書のtrim上限を、品詞・接続IDごとの内部行数ではなく、候補として見える異なる表記（surface）12種類で数えるようにしました。選ばれた表記の品詞・接続ID行は保持するため、文脈変換に必要な接続コストを失いません。（#17）
- 実行時の変換処理でも、従来の先頭12内部行を互換性のため維持しつつ、それらに含まれない表記を最大12種類まで候補へ取り込むようにしました。同一表記の内部行が候補枠を埋めても、別の有用な表記が隠れません。
- 従来の行数上限で失われていた6,563内部行、2,828種類の表記を同梱辞書へ復元しました。個別のallowlistや「縦」専用overlayは追加していません。
- 復元した品詞行が既存語の分類を後から変えないよう、非先頭形の判定根拠を従来の行数上限を通過していた行へ固定しました。独立入力の「版」「日」を保護しつつ、「ずかい」のような非先頭形は従来どおり抑制します。
- 製品方針を「ITエンジニア・ファースト」とし、コード・技術文書・Issue・レビュー・チャット・ターミナルを行き来する入力を主対象にしました。一方で、常用漢字と一般日本語はIT特化のために弱めない品質床として明記しました。

## 検証

- 固定したMozc・smile-chat・Japanese WordNet・審査済み辞書詳細を使って出荷辞書を2回ビルドし、byte-for-byteの決定性を確認しました。`system.dic`は46,920,168 bytes、SHA-256は`ec296b7f68d6d5e55d7faed458473101675e29440dc1e8456998473e60c7632d`です。
- 出荷辞書は611,435 entries、30,846 detailsです。trim reportは、旧行数上限から復元した表記数と、異なる表記12種類の上限外に残る表記数を別々に記録します。
- 実辞書で`たて`の候補ページに`縦`が含まれることを回帰検証しました。内部行が12件連続しても別表記を失わないことを、複数文節・単一文節の両変換方式で確認しています。
- 固定コーパスでは一般語を含むheld-out 60/60、Mozc比較60/60、IT 30/30を維持し、p99変換時間は1.758 msでした。
- workspace全体のformat、test、diff check、残存cargo／rustc／test process 0を確認しています。release workflowでも生成直後の実辞書に対する`たて`→`縦`回帰を必須ゲートとして実行します。

## 対応環境

Windows 11 build 22000以降、x64、AVX対応CPU。32 bitホスト用DLLとARM64ネイティブ版は含みません。

## インストール前の確認

このReleaseはowner承認済みのAuthenticode未署名版です。GitHub Releaseの`sakura_setup.exe`を取得し、同じReleaseにある`release-manifest.txt`のSHA-256とPowerShellの`(Get-FileHash .\sakura_setup.exe -Algorithm SHA256).Hash`が一致することを確認してから手動で実行してください。

未署名installerは自動更新のAuthenticode検証を通らないため、自動取得・実行されません。updaterのfail-closed検証は変更していません。

アップグレードはversioned payloadのside-by-side切替で行われます。新しいpayloadの検証に失敗した場合は、TSF登録を新しい版へ切り替えずに中止します。
