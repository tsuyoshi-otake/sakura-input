# Sakura Input 1.0.37

通信の待ち時間切れや再接続の際に、入力途中の状態と候補表示を不要に失わないよう修正しました。開発者ログから分類した事例を、再現用の回帰テストとともに扱っています（#141）。

## 主な変更

- engineへ要求を送る前にcallbackの期限が切れた場合は、健全な接続とcompositionを保持します。未送信の要求を通信断として扱う経路を修正しました。
- 再接続後に、旧接続の処理が持つcompositionの所有情報によって新しい文字入力が抑止されないよう、接続世代を照合します。
- 応答の送信に失敗した処理から古い候補表示を公開しないようにしました。
- 成功応答済みの同一候補配置の重複通信を抑え、候補の定期取得と配置更新のタイムアウトを診断上で区別します。
- Advancedの修復結果が、無関係な確定操作を介してCommitHistoryへ入る経路を修正しました。

## 検証と残る課題

修正を入れる前に失敗を確認する回帰テスト、workspaceテスト（1,836件成功・85件除外）、Clippy、Releaseビルドを確認しました。同梱済み辞書に対する35件のReleaseテスト、独立した実engine processへの5,000回のIPC計測も成功しました。後者のSendKey p99は0.075 msでした。これは検証環境の通信測定であり、ホストの文書反映や画面描画までの遅延ではありません。

過去ログの各事例の原因をすべて特定したとはしていません。実ホストでの文書反映・候補表示の受入確認と、継続観測は#102・#142・#108で追跡します。VS Codeクラッシュの原因特定や完全な解消を示すリリースではありません。

## 導入方法

このReleaseはowner承認済みのAuthenticode未署名版です。Windowsには「不明な発行元」と表示されます。GitHub Releaseから取得した `sakura_setup.exe` のSHA-256を `release-manifest-v2.txt` と照合して、手動インストールしてください。Sakura固有のmanifest署名は、Windowsのコード署名とは異なります。

## 対応環境

Windows 11 build 22000以降、x64、AVX対応CPU。32 bitホスト用DLLとARM64ネイティブ版は含みません。
