# Sakura Input 2.0.32

今回は2件の修正です。いずれも見た目の入力・変換は変わりませんが、内部の記録と再開が正しくなります（#456、#455、追跡は #461）。

## Shiftで始めた英字の読みを学習・履歴に完全に記録する（#456）

`ChatGPT` や `SSH` のようにShiftで始めた英字の語を確定すると、入力した文字そのものが確定されますが、学習と入力履歴に記録される「読み」には、確定時点でまだかなになっていない末尾のローマ字が欠けていました（`ChatGPT` は `ちゃtgp`、`SSH` は `っ` だけが記録されていました）。これでは後からその読みを打っても予測に出ず、学習が役に立ちませんでした。

今回から、Shiftで始めた英字の確定でも、未確定のローマ字をすべて読みに含めて記録します（`SSH` は `っsh` のように、通常のローマ字入力と同じ読みになります）。読みの構成に失敗した場合でも、確定された文字はそのまま残り、欠けた読みが学習・履歴に書かれることはありません。

## 開発者入力履歴が再起動後に再開する（#455）

明示的な開発者モードで有効化される入力履歴が、PC再起動後に再開しないことがありました。履歴ストアの所有権を「ロックファイルが存在するか」で判断していたため、強制終了などで空のロックファイルが残ると、新しい起動がその空ロックを他人のロックと誤認して起動を拒否していました。

所有権を「排他ハンドルが掴めるか」で判断するように変えたため、残った空のロックは次の起動でそのまま再取得され、履歴は再起動後に再開します。ロック位置がリパースポイント・ディレクトリ・中身のあるファイルだった場合は、履歴サービスが作ったものではないため変更も削除もせずに起動を拒否し、手動で復旧します。

停止している状態が、engineのログ（`history_unavailable`）、`sakura_settings.exe config show` の `developer-history` 行、設定の診断画面で確認できるようになりました。

既存の設定・学習・履歴・ユーザー辞書の形式はそのまま使用できます。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
