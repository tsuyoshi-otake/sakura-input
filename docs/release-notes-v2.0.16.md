# Sakura Input 2.0.16

- 確定した語をBackspaceで消して同じ読みを打ち直し、別の表記で確定したとき、その操作を「訂正」として学習に反映するようにしました（#305）。これまでは、消した表記の学習が残り、同じ文脈で再び先頭に出ることがありました。訂正のあとは、消した語の直前の文脈では、消した表記を学習で先頭に上げず、打ち直した表記を先頭にします。確定直後のCtrl+Backspace（確定の取り消し）で消した場合も対象です。打ち直しをカナ変換（F6〜F10、無変換）で確定した場合も訂正として扱います。
- 訂正が効くのは、消した語の直前の文脈だけです。ほかの文脈での順位、気づかずに残した誤変換、入力途中の予測候補の並びは変わりません。打ち直したときの変換では、これまでどおり消した表記が先に出ることがあります。訂正が効くのは、その次の変換からです。パスワード、URL、メールアドレス、数字の欄では訂正を記録しません。
- 訂正で下げた表記を同じ文脈で選び直すと、その訂正の記録は外れます。予測候補をCtrl+Deleteで削除した場合も、その表記の訂正の記録は消えます。設定の `learning export` と `learning show` には、訂正の記録が `#reject` で始まる行として、学習の表の後に出力されます。
- 訂正の記録は既存の学習ログの形式で保存されます。2.0.15以前に戻しても順位は変わらず、学習ログを消す必要はありません。辞書と設定は変わりません。

このリリースの検証は、訂正の検出・学習・保存のテスト、変換エンジンのキー処理のテスト（修正前のコードでは失敗することの確認を含む）、開発者の20日分の入力履歴を使った再生評価、ワークスペース全体のテスト、リポジトリのCIゲートです。再生評価では、先頭の候補が変わる変換が31回ありました。そのうち、新しい先頭がユーザーの最終的な選択と一致したものが23回、元の先頭が一致していたのに外れたものが6回でした。辞書は2.0.15から変わっていません。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では署名付き更新manifestによるサイズ・SHA-256・未署名状態の検証を行います。
