## Issue #360 堅牢化で owner が決めた扱い（2026-10-18）

- 状態: 実装済み（各項目の採点表が independent verifier で overall=pass）
- 対象: `crates/sakura-store`（学習ログ）、`crates/sakura-renderer`（Pad）、`crates/sakura-tsf` と `crates/sakura-engine`（入力スコープ、学習、composition fence）
- ここには owner が選んだ方針だけを書く。実装の詳細と検証結果は `.claude/memory/journal.md` の #360 の項目にある。

### A3 学習ログの途中が読めないとき

- 方針: 読めた内容をコピーへ退避してから、壊れた場所より前のレコードで学習を続ける。
- コピーは `log.corrupt-<UTC の日時>` で、新しい 3 個まで残す。コピーを作れないときは `log.bin` を変えず、そのセッションの学習を保存しない。
- 末尾の書きかけ（短い残り、ファイル末尾を越える長さ、全部 0 の残り）は、これまでどおりコピーせずに切り詰める。
- 消去はコピーも削除する。削除できなければ消去を失敗させ、`log.bin` を変えない。

### #3 TOTP の時計が過去へ戻ったとき

- 方針: 下限をリセットする。
- 30 秒ステップ 3 つ分以上戻ったときは、記録した最大ステップを現在へ戻し、失敗として数えない。直前の失敗による待機は、1 回分の待機より長くならないようにだけ縮める（延ばさない、消さない）。
- 1〜2 ステップの戻りは、これまでどおり失敗として数える。

### A6 保護メモのコピーとクリップボード履歴

- 方針: 保護メモのコピーだけを、クリップボード履歴（Win+V）とクラウドクリップボードから外す。
- 解除中の保護メモのコピーは、`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory`=0、`CanUploadToCloudClipboard`=0 を同じクリップボードセッションに置く。印を置けないときは何もコピーしない。
- 保護を設定していないメモのコピーは変えない。`SetWindowDisplayAffinity` による画面キャプチャ対策は扱わない。

### A8 入力スコープを読めなかったフィールドの学習

- 方針: 既知の `E_FAIL` 以外は学習しない。
- WinForms と従来の EDIT が返す `E_FAIL` は、これまでどおり通常のフィールドとして扱う。
- それ以外のエラーで入力スコープを読めなかったフィールドは `Unclassified` とし、入力履歴と同じく学習も止める。一部のアプリで学習、AI 文章変換、rerank が効かなくなることは受け入れる。

### A9 idle Space の composition fence のキー

- 方針: プロセス名の偽装だけを防ぐ。
- fence のキーは、接続した client の PID（カーネルが報告する値）から得たイメージのファイル名にする。読めないときは `pid:<n>` にし、読めなかったことを記録する。`CreateSession` で client が名乗ったプロセス名は、fence のキーには使わない。アプリプロファイルとホストポリシーは、これまでどおりこの名前で選ぶ。
- 同じファイル名のプロセス同士は、これまでどおりカウントを共有する。信頼度の低い client も、これまでどおり学習する。

### bak 旧形式から変換したときのバックアップ

- 方針: 消去で削除する。
- 消去（設定画面、`sakura_settings.exe learning clear`）は、旧形式から変換したときのバックアップ `log.v{N}.bak`（`log.v1.bak`／`log.v2.bak`、番号付きの名前を含む）も削除する。通常のファイルだけを削除する。削除できなければ消去を失敗させ、`log.bin` を変えない。
- 学習した項目を 1 件だけ削除しても、バックアップは変えない。起動時の復旧は、これまでどおりバックアップを削除しない。
