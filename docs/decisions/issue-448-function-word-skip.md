## Issue #448 機能語の読みを「読み飛ばし規則」の対象から外す（2026-11-14 のオーナー指示として記録）

- 背景：`preferred_candidate_index`（`crates/sakura-engine/src/dispatch.rs`）は、候補一覧の1行目が読みそのもの（ひらがな）のとき、その行を飛ばして読みと違う最初の行を選ぶ。この規則は所有者の履歴測定で 473 回中 391 回は正しかった一方、機能語・補助動詞・副詞のような短い読みでは飛ばした先が使われにくい漢字やカタカナになり、ひらがなが正解の場面で誤った候補が最初に出ていた（2.0.32 の開発者ログでも `ばかり`→`バカリ` を実観測、#467）。
- 決定：オーナーは 2026-11-14 に「機能語（助詞や助動詞のまとまり）を #448 の読み飛ばし規則の対象から外す方向で直し、その決定を docs/decisions に記録する」と指示した。Issue 本文の案 B に相当する。
- 判定方法：1行目の候補が読みと同じ表記で、その候補を構成する**すべて**の辺の接続クラス（right_id）が 500 未満のとき、その読みは機能語のまとまりとして扱い、読み飛ばしをしない（1行目を選ぶ）。接続クラス 500 未満は辞書の助詞・助動詞・接続語尾の帯である。2.0.32 の `system.dic` で実測すると、ばかり=310、だけ=296、から=330、ながら=355、ので=359、のに=360、には=283、になって（に=372／なって=348）がすべてこの帯に入り、動詞・名詞のかな表記（してる=1097、カタカナ名詞は1851帯）は上に残る。複数辺のひらがな経路（になって、では）にも同じ規則が効く。
- 変えないこと：学習済み・確定済みの候補設定（learned / cached preference）はこの免除より先に効く。読みと違う1行目、機能語帯より上のクラスを持つかな表記の読み飛ばしは従来どおり残る（例：かな表記が動詞語幹クラスの読みでは漢字が選ばれ続ける）。文全体の経路を優先する文節選択（`initial_segment_selections`）は Issue 本文どおり対象外のまま。
- 意図：ひらがなに戻した 11 回の型を消しつつ、規則が正しかった 391 回の側（読み飛ばした先が普通の漢字の名詞・動詞の読み）を壊さない。クラス境界 500 は語彙の追加で機能語のかな行が帯から外れ得る点が既知の限界で、新しい帯の語はこの決定の更新として扱う。
- テスト：`crates/sakura-engine/src/dispatch_tests.rs` の `a_function_word_reading_keeps_its_hiragana_first_row`。合成辞書で「クラス310のかな行が先頭の読み」は1行目を選び、「クラス700のかな行が先頭の読み」は従来どおり読みを飛ばすことを固定する。修正前のコードで失敗する（1行目が飛ばされて Some(1) が選ばれる）。
