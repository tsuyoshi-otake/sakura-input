# Sakura Input 1.0.1

1.0.0 に対する修正リリースです。候補ポップアップの出現位置だけが変わり、変換・予測・辞書・キー操作は 1.0.0 と同じです。

## 修正

- 候補ポップアップが入力欄を塞ぐ問題を修正しました（#47）。これまでは変換中の文字列（composition）だけを基準に配置していたため、複数行の入力欄では「文字列の下」が入力欄の中になり、候補一覧が入力中のテキストの上に重なることがありました。TSF の `ITfContextView::GetScreenExt` で編集領域そのものを取得し、配置の判断に使うようにしました。
- 併せて、入力欄を避けるためにポップアップがキャレットから離れすぎないよう、迂回できる距離に上限（論理 160 px、候補約 5 行分）を設けました。背の高いエディタのように近くへ避け場所がない場合は、これまでどおりキャレット直下に表示します。画面下端のチャット入力欄のように、少し動かすだけで入力済みのテキストを避けられる場合だけ位置を変えます。

実測では、884×581 の入力欄でキャレット行の 4 px 下、画面下端の 884×121 の入力欄では入力欄の上端から 5 px・キャレットから 55 px の位置に表示されます。

## 内部の変更

- engine と renderer 間のプロトコルを v16 に更新しました（編集領域の矩形を追加）。TSF DLL・engine・renderer は同一バージョンで同梱されるため、混在構成は発生しません。
- ホストが編集領域を返さない場合は、1.0.0 と同じ composition 基準の配置に fail closed します。

## 対応環境

Windows 11 build 22000 以降、x64、AVX 対応 CPU。32 bit ホスト用 DLL と ARM64 ネイティブ版は含みません。

## インストール前の確認

このリリースの `sakura_setup.exe` は 1.0.0 と同じくローカルビルドで、Authenticode 署名を含みません。署名の検証はできないため、ダウンロード元と SHA-256 を確認したうえでインストールしてください。署名が必要な場合は、署名証明書の secret を登録したうえで Actions の署名付きリリースワークフローを使ってください。

アップグレードは versioned payload の side-by-side 切替で行われるため、通常の終了コードは `0` で、TSF DLL が使用中でも Windows の再起動は要求されません。ロックされた旧世代は、SYSTEM のログオン時メンテナンスタスクが後で削除を再試行します。

詳細は同梱の `README-ja.md` と `guide-ja.md` を参照してください。
