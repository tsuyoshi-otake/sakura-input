# Sakura Input 2.0.4

変換候補の一覧が消えずに残る問題について、再現できた3つの経路を修正しました（#255）。

## 主な変更

- 候補表示の通信が切れた・タイムアウトした・不正な応答を受け取った場合、再接続を待つ前に古い候補とクリック領域を隠します。未処理の古い表示通知で候補が復活することを防ぎ、再接続後の新しい候補は表示できます。
- 入力元アプリとの接続が切れた場合、エンジンに残っていた候補と表示位置を破棄します。別の入力元が新しく表示した候補は保持します。
- 画面倍率変更やウィンドウ配置の異常処理で、内部的には非表示なのに候補の表示だけが残る分岐を修正しました。候補の表示、クリック領域、アクセシビリティの状態を一緒に非表示にし、次の正常な更新で復帰します。

## 検証と確認範囲

通信断・入力元の切断・配置失敗を修正前にテストで再現し、修正後に消去と復帰を確認しています。入力元の切断は独立したテスト用エンジン、配置失敗は実際の候補ウィンドウへの異常入力で検証しました。通常のモニター切り替えで必ず問題が起きるという意味ではありません。

既存の通信タイムアウトは変更していないため、応答停止を検出するまで候補が残る場合があります。報告されたすべての発生条件の解消を確認したものではありません。辞書、変換順位、キー操作、設定の保存形式、通信プロトコル版22は変更していません。

## 導入方法

このリリースはowner承認済みのAuthenticode未署名版です。Windowsには「不明な発行元」と表示されます。GitHub Releaseから取得した `sakura_setup.exe` のSHA-256を `release-manifest-v2.txt` と照合してインストールしてください。Sakura固有のmanifest署名はWindowsのコード署名とは異なります。

対応する更新機能では、固定公開鍵によるmanifest署名、installerのサイズとSHA-256、manifestの未署名指定、およびWindowsの「署名なし」判定がすべて一致する場合に限り、未署名版も自動更新で導入できます。それ以外の署名検証エラーは拒否します。

対応環境はWindows 11 build 22000以降、x64、AVXとSSSE3の両方に対応したCPUです。
