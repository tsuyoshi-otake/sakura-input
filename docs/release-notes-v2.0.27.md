# Sakura Input 2.0.27

日本語入力の診断ログがキー応答を遅らせる経路を改善し、読取専用欄への不要な変換処理と、AI文章変換・履歴収集のエラー案内を改善しました（#434、#435、#411）。

- 開発者モードのエンジン診断ログを、件数に上限のあるキュー経由で別スレッドに保存します。保存が遅れてもキー処理は保存完了を待ちません。キューが満杯の場合は診断行を破棄して件数を数えます。ホストアプリ内のTSF DLLには新しいログ用スレッドを作りません。
- 変換中ではない入力欄が読取専用と報告された場合、文字・Space・変換キーによる新しい書込み処理を開始しません。変換中の文字や処理中の確定・復旧は、既存の終了処理が扱います。
- AI文章変換でモデル・Effort・Tierの指定をAPIが拒否した場合、確認すべき設定や利用権限を案内します。APIから返された自由文や入力内容をエラーコードへ取り込まず、モデルやTierを自動で変更することもありません。
- `history stats` に履歴件数・最新の保存時刻・未検証の末尾バイト数を追加しました。保存失敗の件数が0でも収集サービスが停止している場合を区別できます。
- `config set developer-mode on` は、長い履歴の初期化を3秒で打ち切らず、最大180秒の確認枠で状態を待ちます。確認間隔を段階的に広げ、確認できない場合は「設定は保存済み・稼働状態は未確認」と、`history stats` で確認する手順を表示します。個々の通信には既存の期限が適用されます。残存ロックを自動で削除することはありません。

検証では、実エンジンの診断ログ保存に200ミリ秒の遅延を入れても、キー応答が50ミリ秒以内に返り、入力中の文字と確定内容が保たれることを確認しました。保存完了を待つ処理へ戻すと同じテストがタイムアウトし、履歴の確認枠を3秒へ戻すと初期化待ちのテストが失敗します。ワークスペースの2,670件のテスト、静的解析、配布用ビルド、精度・インストーラー検査も通過しました。これは診断ログ保存による遅延経路の検証であり、すべての入力タイムアウト原因が解消したことを意味しません。

既存の設定・学習・履歴形式はそのまま使用できます。診断ログの終了処理は進行中のOS書込みを待つため、OS側の書込み停止による終了待ちは残ります。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
