# Sakura Input 2.0.29

時刻・週を表す数の変換を直し、数詞と助数詞の読みでユーザー辞書の登録語が候補から消える問題を修正しました。あわせて、長い読みの変換で使う任意のローカル再順位付けモデルを sakura-rerank Issue #29 の蒸留モデルに替え、確信度ゲートを加えました（#341、#439、#440）。2.0.28 はタグを作成しただけで公開していません。2.0.28 の変更はすべてこの版に含まれます。

- 時・時間・時半・週・週間の読み（例：じゅういちじ、にしゅうかん）では、`十一時`・`二週間` を先頭に出し、算用数字の候補も残します。これまでは `重一時`・`に習慣` を選んで確定することがありました。数字キーで入力した変換、同音の語、数を含む辞書の語、`三時間ほど眠った` のような変換、`時半`・`週間後` の変換は変えていません。分・円の助数詞は今回の対象外です（#341）。
- 読み全体が数詞と助数詞になる場合（例：にじ、にがつ、にしゅうかん、じゅういちじ）、ユーザー辞書の登録語が候補から消えていました。月・年の読みでは 2.0.27 以前から起きていました。登録語は候補に残り、登録語自身のコストで並びます。先頭に出ることは保証しません。ほかの候補の並びは変わりません（#439）。
- 同梱モデルを `Sakura-Rerank-Tiny-v1-issue29-distilled` に替えました。モデルとの通信形式（protocol v1）、配置先、既定の対象範囲（`LongTextOnly`）は変わりません。既存設定が `off` の場合も、これまでどおり上書きしません（#440）。
- 辞書と学習で決まったローカルの第1候補を、モデルが選んだ候補に置き換えるのは、モデルの評価値（logit）の差が1.7を超えるときだけです。差が1.7以下の場合、同じ候補の場合、評価できない場合は、ローカルの第1候補をそのまま使います。モデルの入力には候補ごとのローカルコスト差を加えました（7項目）。文脈と読みは引き続きモデルへ渡しません。
- workerは、モデルのSHA-256・サイズ・選択規則（規則名と閾値1.7）をmanifestで照合します。一致しない場合は起動時にモデルを使わず、元の順位のまま動作します。

時刻・週の変換は、2.0.27と同じ辞書で1,587件の変換例を比べ、8件改善・0件悪化、予測語1,605件は変化なしでした。助数詞・同音語・日付の243件の追加確認では121件改善・0件悪化です。ユーザー辞書の修正は、修正前に失敗するテストを用意し、候補選択から確定までを確認しました。

再順位付けモデルは、研究側のdev参照（1,788件、AI教師ラベル、独立したTestではない）で、入力を製品と同じ条件に揃えて比べました。2.0.27のモデルは正解1,630件・誤った置換14件、今回のモデルとゲートは正解1,611件・誤った置換3件でした。これは精度向上ではなく、誤った置換を減らす安全側の変更です。研究時点のGate Aは未通過のままで、品質gate合格を意味しません。研究実装から作った276件の合成ケースで、モデル入力がビット単位で一致すること、配布用workerのスコア差が1e-4以内であること、選択結果が一致することを確認しました。Windows CPUでの10,000回の往復は失敗0件、p95 0.77ミリ秒でした。

既存の設定・学習・履歴形式はそのまま使用できます。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
