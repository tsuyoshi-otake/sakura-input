# Sakura Input 2.0.31

学習も文脈もない状態で、読みだけを打って最初の候補に出る語を5件直しました（#454）。履歴やユーザー辞書の登録語がある変換は変わりません。

- `しょうき` と打つと `正気` が先頭に出ます（これまで `章気` が先頭でした）。
- `だいぜん` と打つと `大全` が先頭に出ます（`大全` の標準読みは `たいぜん` ですが、`だいぜん` も入力した読みとして変換します）。
- `てすとだいぜん` と打つと `テスト大全` が先頭に出ます。
- `ひんじゃくそう` と打つと `貧弱そう` が先頭に出ます（IT語のまとまりを優先する仕組みが、末尾の `層` をIT用語の複合とみなして `貧弱層` を先頭にしていました。`ぜいじゃくそう` も同じく `脆弱そう` になります）。
- `とらんすくりぷと` と打つと `トランスクリプト` が先頭に出ます（`トランス区リプション` と分割されていました）。
- `いじれる` をひらがなで変換するようになりました（これまで `弄れる` が先頭でした）。`みぎくりっくでいじれるように` は `右クリックでいじれるように` と変換します。

`層` をIT用語の複合とみなす仕組みは、本物の複合（`ネットワーク層` `開発者層` `ユーザー層` など）はそのまま維持しつつ、`そう` の読みの末尾にだけ効かない範囲に絞り込みました。`しょうきですか` や `ひんじゃくそうなんじゃない` など、従来から正しく変換できていた読みは変わりません。

それぞれの修正について、修正前のコードで失敗するテストを用意しました。一般の日本語変換の精度ゲート（`accuracy-gate --check`）は合格で、結果は 2.0.30 から変わっていません。インストールした状態での画面の確認はしていません。

既存の設定・学習・履歴・ユーザー辞書の形式はそのまま使用できます。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
