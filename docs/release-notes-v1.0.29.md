# Sakura Input 1.0.29

変換の中身に手を入れたリリースです。同音語のカバレッジ、単漢字、候補数上限、句読点、IT 用語の読みを広げ、変換直後に全角スペースが入る不具合を直しました。

## 主な変更

### 変換候補

- 同音語が辞書にあるのに出ない問題を直しました。ビルド時の trim が読みごとに 12 表記で打ち切っており、963 の読みから 10,781 表記が同梱辞書へ届く前に落ちていました。`きかん` から気管・旗艦・季刊、`かん` から関・環、`こう` から光・行が戻ります。あわせて 8 つの読みの順位を付け直し、`たいあん` が大安より先に対案を出す状態を解消しました。（#94）
- 単漢字辞書を同梱しました。`ひ` のような一モーラの読みは、候補数を増やしても辞書側が尽きていて 19 候補で打ち止まっていました。Mozc と同じ形で、変換の後段に単漢字表を付け加えます。取り込みは版を固定したうえで厳密に解析し、解釈できない行はスキップではなくビルドの失敗にします。（#95）
- 候補数の上限を 18 から 256 へ引き上げました。この値は表示上の上限ではなく探索そのものの上限なので、読みの長さごとに実測した p95 遅延に基づいて予算を配分します。短い読みほど広く探索し、長い読みでは従来どおりの範囲にとどめます。（#95）

### 句読点と表記スタイル

- 句読点の設定に半角の `,` と `.` を追加しました。読点・句点をそれぞれ独立に選べるようになり、9 通りの組み合わせが指定できます。Markdown や LaTeX から組版する文書では全角の `．` は誤りなので、従来の 4 択では足りていませんでした。あわせて、組み合わせ全体を一度に切り替える表記スタイルのプリセットを追加しました。（#96, #97）
- 句読点を変換したときに、同じ役割の記号をすべて候補に出すようにしました。従来は設定した記号以外が候補から消えていたため、`，．` を設定した読者が一文だけ読点を打つには設定画面を開く必要がありました。設定は候補の並び順を決めるだけで、一覧は網羅されます。ATOK と同じ考え方です。（#99）
- その一覧で、設定した記号ではなく 3 行目が既定で選ばれていた不具合を直しました。設定画面に `、` と表示されているのに `，` が確定される状態でした。この機能を入れる前は全ての行が設定した字形で描かれていたため表面化していませんでした。（#99）

### IT 用語

- かな入力から IT 用語へ届かない問題を直しました。同梱の用語表は用語集から生成しており、日本語の語義は持っていても利用者が実際に打つ読みを持っていませんでした。頭字語 687 語のうちアルファベット綴りで引けるのは 190 語だけで、`じーぴーゆー` が `CPU` を先頭に出すなど、無い候補より質の悪い誤答が出ていました。プロジェクト側の overlay を 92 行から 1,006 行へ広げ、綴りで引ける頭字語は 662 語になります。（#101）
- 一般日本語の劣化がないことは主張ではなく測定で担保しています。かな読みの行は変換専用にとどめ、予測へは出しません。かな読みは通常の語と前置部を共有するため、そこを開けると IT 用語の利得と引き換えに一般語の回帰を招きます。（#101）

### 不具合の修正

- 変換を確定した直後の Space が全角スペースになることがある不具合を直しました。キー送信が DLL の 50 ms 予算を超えるとパイプが落ち、再接続で空のセッションを受け取ります。このとき変換中だったセッションは読みを抱えたまま破棄され、その次の Space は「入力のない状態の Space」として全角スペースを確定していました。破棄が起きた場合に限り、その 1 回の Space を吸収するようにしました。（#102）
- 変換ホットパスのスタック使用量を削減しました。実測で 136 KiB を要求していた経路を 68 KiB 未満に収め、worker の予約内に余裕を戻しています。（#103）

## 含まれないもの

- **50 ms のキー予算を超える原因そのものは未解明です。** 上記の修正は、超えたときに全角スペースが入る被害を止めるものであって、超える頻度を下げるものではありません。
- 候補数上限の設計（読み長による clamp と遅延 N-best 展開のどちらを採るか）は #100 / #103 で継続審議中です。このリリースは読み長 clamp を採っています。
- **Sakura Pad の GitHub 同期は未実装です。** 下部バーの同期ボタンは「GitHub 未設定」と表示するだけで、通信は行いません。メモは端末内にとどまります。
- Pad の dark テーマと Windows ハイコントラストは、自動検証だけで実画面確認が済んでいません。
- Pad 一覧の検索はタイトルと本文の部分一致ですが、英字の大文字小文字を無視するだけで、全角・半角やひらがな・カタカナの正規化は行いません。

## 検証

- workspace 全体の format、Clippy（`-D warnings`）、`cargo test --workspace` に成功しました。
- 辞書は 2 パスで同一の結果になることを確認したうえで同梱しています。単漢字表の取り込みでは、読みとして打てない 2 行だけを既知の例外として許可し、3 行目が現れた場合はビルドを止めます。
- 候補数上限の引き上げは、実際の同梱辞書に対する読み長別の p95 遅延測定に基づいています。IT 用語の追加は、全候補一覧の差分を測って一般日本語側の回帰がないことを確認しています。

## 対応環境

Windows 11 build 22000 以降、x64、AVX 対応 CPU。32 bit ホスト用 DLL と ARM64 ネイティブ版は含みません。

## インストール前の確認

この Release は owner 承認済みの Authenticode 未署名版です。GitHub Release の `sakura_setup.exe` を取得し、同じ Release にある `release-manifest.txt` の SHA-256 と PowerShell の `(Get-FileHash .\sakura_setup.exe -Algorithm SHA256).Hash` が一致することを確認してから手動で実行してください。

未署名 installer は自動更新の Authenticode 検証を通らないため、自動取得・実行されません。updater の fail-closed 動作は維持されます。

アップグレードは versioned payload の side-by-side 切替で行われます。新しい payload の検証に失敗した場合は、TSF 登録を新しい版へ切り替えずに中止します。
