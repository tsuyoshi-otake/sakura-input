# Sakura Input 2.0.15

- CPUの負荷が高いとき（ビルド中など）に、文字入力や変換のキーが取りこぼされ、入力中の文字が途中で確定されることがある問題を修正しました（#322）。原因は、ログオン時にSakura Inputを起動するタスクの優先度が「通常以下」で、変換エンジンと候補ウィンドウを表示するプロセスもその優先度を引き継いでいたことです。キーを受け取ったアプリは変換エンジンの応答を最大50ミリ秒しか待たないため、ほかのプログラムがCPUを使い切っていると応答が間に合いませんでした。変換エンジンは「通常以上」、表示プロセスは「通常」の優先度で動くようにしました。長文変換やAIテキスト変換の重い補助プロセスは、これまでどおり「通常以下」で動きます。
- 変換結果、学習、設定、辞書は変わりません。変換エンジンのログ（`engine.log`）には、起動時に引き継いだ優先度と設定した優先度が記録されます。

このリリースの検証は、「通常以下」で起動した変換エンジンと表示プロセスがそれぞれ自分の優先度を上げることの実プロセステスト（修正前のコードでは失敗することの確認を含む）、CPUを飽和させた状態でのキー応答時間の計測、ワークスペース全体のテスト、リポジトリのCIゲートです。計測では、「通常以下」のエンジンは4回の計測すべてで50ミリ秒を超えるキーがあり、最悪で約10秒止まりました。「通常以上」では最大0.34ミリ秒でした。辞書は2.0.14から変わっていません。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。
