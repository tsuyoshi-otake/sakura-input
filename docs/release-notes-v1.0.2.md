# Sakura Input 1.0.2

1.0.1 に対する修正リリースです。数字の読みに対する候補の並びだけが変わり、キー操作・UI・変換エンジン・プロトコルは 1.0.1 と同じです。

## 修正

- 数字の読みで算用数字が単語より先に出る問題を修正しました（#48）。「いち」と入力すると `1` が `市`・`位置`・`一` より先に出るなど、一桁の読み 11 件のうち 7 件で算用数字が第 1 候補を取っていました。上流の Mozc は算用数字をひとつの数詞クラスにまとめ、同じ読みを持つ単語よりはるかに安く値付けしています。Sakura には数値の書き換え器がなく格子コストがそのまま候補順になるため、他の IME では起きないこの並びがそのまま表に出ていました。

  算用数字は数詞の表記であって独立した単語ではないので、辞書の校正レイヤーで各数字を同じ読みの漢数字（`はち` なら `八`）のちょうど 60 だけ後ろへ置き直しました。刈り込み済みの語彙に漢数字を持たない `よん`・`ぜろ` は、その読みの最後の通常語の後ろに置いています。数字は第 1 候補ページに残ったまま、漢数字の次に並びます。

  校正したのは `いち`・`に`・`さん`・`よん`・`ご`・`ろく`・`なな`・`はち`・`きゅう`・`ぜろ`・`れい` の 11 読みです。既存のエッジを置き換えるだけで、候補を追加も削除もしていません。`いちがつ → 1月`、`ついたち → 1日` のような複合語の表記は従来どおり入力できます。

## 内部の変更

- 辞書ビルダーが行の列数超過を検出できない不具合を修正しました（#49）。`splitn` で分割数を上限で打ち切っていたため、余分な列が最後の列（注記欄）へ畳み込まれ、直後の列数チェックを素通りしていました。注記欄は候補ポップアップでユーザーに見える文字列です。出荷データに該当する行は 1 件もなく、この修正でコンパイル済み辞書の内容は変わりません。
- 辞書ビルダーの各入力フォーマット（Sakura の校正レイヤー、Mozc 辞書、両形式の接続行列）に、条件網羅テストと固定 seed の生成テストを追加しました。条件数を凍結しているため、条件の増減は明示的な変更としてしか行えません。

## 対応環境

Windows 11 build 22000 以降、x64、AVX 対応 CPU。32 bit ホスト用 DLL と ARM64 ネイティブ版は含みません。

## インストール前の確認

このリリースの `sakura_setup.exe` は 1.0.0・1.0.1 と同じくローカルビルドで、Authenticode 署名を含みません。署名の検証はできないため、ダウンロード元と SHA-256 を確認したうえでインストールしてください。署名が必要な場合は、署名証明書の secret を登録したうえで Actions の署名付きリリースワークフローを使ってください。

アップグレードは versioned payload の side-by-side 切替で行われるため、通常の終了コードは `0` で、TSF DLL が使用中でも Windows の再起動は要求されません。ロックされた旧世代は、SYSTEM のログオン時メンテナンスタスクが後で削除を再試行します。

詳細は同梱の `README-ja.md` と `guide-ja.md` を参照してください。
