# Sakura Input 2.0.35

今回は、VPN などのネットワークで更新の確認が失敗しやすかった問題を改善しました（#484）。

## 更新の確認と取得

更新情報の取得が「WinHttpReceiveResponse failed: 0x80072EFE」で失敗することがありました。更新の通信で、前の通信の接続を使い回さないようにしました。

応答を受け取る前に接続が切れた場合は、少し待って最大3回まで自動で試し直します。接続できない、時間切れ、証明書の失敗、サーバーからのエラー応答、ダウンロードの途中で切れた場合は、従来どおり試し直さずに失敗として表示します。

失敗したときの表示に、接続先のホスト名と、試し直した場合はその回数が入るようになりました。

更新の接続先の制限、サイズ上限、時間制限、署名と内容の検証は変わりません。変換、設定、学習、ユーザー辞書の動作と形式にも変更はありません。

この修正は、2.0.35 に更新した後の更新確認から効きます。2.0.34 以前で更新確認が失敗する場合は、もう一度「今すぐ確認」を試すか、GitHub Release から手動で導入してください。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
