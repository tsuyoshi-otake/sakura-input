# Sakura Input 2.0.28

この版はタグを作成しただけで、公開していません。変更はすべて2.0.29に含まれます（#443）。

長い読みの変換で使う任意のローカル再順位付けモデルを、sakura-rerank Issue #29 の蒸留モデルに替え、確信度ゲートを加えました（#440）。

- 同梱モデルを `Sakura-Rerank-Tiny-v1-issue29-distilled` に替えました。モデルとの通信形式（protocol v1）、配置先、既定の対象範囲（`LongTextOnly`）は変わりません。既存設定が `off` の場合も、これまでどおり上書きしません。
- 辞書と学習で決まったローカルの第1候補を、モデルが選んだ候補に置き換えるのは、モデルの評価値（logit）の差が1.7を超えるときだけです。差が1.7以下の場合、同じ候補の場合、評価できない場合は、ローカルの第1候補をそのまま使います。
- モデルの入力に、候補ごとのローカルコスト差を加えました（7項目）。文脈と読みは引き続きモデルへ渡しません。
- workerは、モデルのSHA-256・サイズ・選択規則（規則名と閾値1.7）をmanifestで照合します。一致しない場合は起動時にモデルを使わず、元の順位のまま動作します。

研究側のdev参照（1,788件、AI教師ラベル、独立したTestではない）で、入力を製品と同じ条件に揃えて比べました。2.0.27のモデルは正解1,630件・誤った置換14件、今回のモデルとゲートは正解1,611件・誤った置換3件でした。これは精度向上ではなく、誤った置換を減らす安全側の変更です。研究時点のGate Aは未通過のままで、品質gate合格を意味しません。

検証では、研究実装から作った276件の合成ケースで、次の3点を確認しました。モデル入力がビット単位で一致すること、配布用workerのスコア差が1e-4以内であること、選択結果が一致することです。Windows CPUでの10,000回の往復は失敗0件、p95 0.77ミリ秒でした。

既存の設定・学習・履歴形式はそのまま使用できます。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseの更新manifestに記録されたサイズ・SHA-256とファイルを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
