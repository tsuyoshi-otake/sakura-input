# Sakura Input 2.0.18

このリリースは、安全性と堅牢性の修正（#360）です。変換の辞書は変わりません。

- インストール先を Program Files 内のフォルダーに限定しました。Program Files 以外にインストールされた Sakura Input を更新しようとすると、インストーラーはエラーで停止します。この場合は先にアンインストールしてから、Program Files 内に再インストールしてください。インストール先の各フォルダーが、管理者以外のユーザーから書き換えられないことも、登録の前に確認します。
- Sakura Input の TSF の DLL は、アプリで一度使われたら、そのアプリが終了するまで読み込んだままにするようにしました。アプリが DLL を解放しようとしたあとに、残ったウィンドウの処理が解放済みのコードを呼ぶことを防ぎます。
- AI テキスト変換の待機カーソルを、送信の成功・失敗・キャンセルのどの場合でも元に戻すようにしました。マウスの下にあるアプリが応答しない場合でも、カーソルを戻す処理で入力中のアプリが止まらないようにしました。
- AI テキスト変換で Codex CLI を使う場合、リクエストごとに新しい空の作業ディレクトリ（`%LOCALAPPDATA%\SakuraInput\ai-codex-tmp` 以下）で実行するようにしました。キャンセルやタイムアウトで残った作業ディレクトリは、作成から10分以上たったものを後続のリクエストが削除します。
- リランカーのモデル（`model.onnx`）は、プログラムに組み込んだハッシュとサイズに一致する場合だけ使います。一致しないモデルは使わず、従来のローカル順位で変換します。
- 学習ログの安全性を高めました。
  - 学習ログ全体を書き直す処理（圧縮、消去、旧形式からの変換）は、一時ファイルに書き込んでから1回の置換で反映します。中断で残った一時ファイルは、次に開くときに削除します。
  - 学習ログの途中が読めない場合は、読み込んだ内容を `learning\log.corrupt-<UTC の日時>` にコピーしてから、壊れた場所より前の学習で続けます（コピーは最新3件を保持）。コピーを作成できないときは `log.bin` を変更しません。
  - 学習の消去（設定画面、または `sakura_settings.exe learning clear`）で、旧形式から変換したときに残る `log.v1.bak`／`log.v2.bak` と、上のコピーも削除するようにしました。どれか1つでも削除できないときは消去が失敗し、学習内容はそのまま残ります。学習した項目を1件だけ削除しても、これらのファイルは変わりません。
  - Windows が入力欄の種類（入力スコープ）を報告できなかった入力欄では、学習しないようにしました。WinForms や従来の EDIT コントロールが返すエラー（E_FAIL）の入力欄は、これまでどおり学習します。
- Pad の安全性を高めました。
  - 解除中の保護メモをコピーすると、Windows のクリップボード履歴（Win+V）とクラウドクリップボードに残らないようにマークを付けてコピーします。マークを付けられない場合はコピーしません。保護を設定していないメモのコピーは従来どおりです。
  - TOTP の状態保存が途中で中断された場合は、次に読み出すときに、書き終わっていた保存を適用し、書きかけの保存を破棄します。
  - Windows の時計が30秒ステップ3つ分以上過去に戻った場合は、記録した時刻を現在時刻に合わせ直します。直前の失敗による待機（最大約60秒）のあとで、正しいコードが再び受け付けられます。
- Cursor などで1回の Space が同じアプリの複数の入力欄に届くとき、変換中の入力欄があれば、入力していない入力欄には全角スペースを入れません。このとき同じアプリかどうかを、アプリが名乗る名前ではなく、Windows が報告するプロセスの実行ファイル名で判定するようにしました。ほかのアプリの名前を名乗る接続が、そのアプリの Space 入力を止めることはできません。

2.0.17までに学習した内容と設定は、そのまま使われます。

検証は、各項目のテスト（修正前のコードで失敗すること、意図的に入れた不具合を検出することを含む）、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認（Win+V の履歴、時計の巻き戻し、WinForms での学習、2つのアプリ間の Space など）は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
