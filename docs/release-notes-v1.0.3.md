# Sakura Input 1.0.3

1.0.2 に対する修正リリースです。入力状態機械の 1 件の不具合だけを直しており、UI・変換エンジン・辞書・プロトコルは 1.0.2 と同じです。同梱辞書もバイト単位で同一です。

## 修正

- Shift で始めた英語入力を確定せずに消すと、日本語入力へ戻れなくなる問題を修正しました（#51）。

  ASCII の 1 文字目に Shift を押すと、その入力中だけ一時的に英語入力へ切り替わります。この一時モードは、確定・取り消しのどちらかで終わるはずでした。ところが Backspace で 1 文字ずつ消し切った場合はそのどちらにも到達せず、画面には何も残っていないのに一時モードだけが残りました。

  この状態からは抜け出せませんでした。以後の入力はすべてローマ字のまま英語として表示され、実測した限り Escape、Enter、Space、無変換、変換、かなキー、Backspace のいずれを押しても解除できませんでした。解除できるはずの Escape と Enter は「入力中の文字列があること」が条件で、まさにそれが失われた状態だったためです。他の IME へ切り替えて戻すと直ったのは、そのとき入力セッションが作り直されるからです。

  一時英語モードは入力中の文字列に付随する状態なので、その文字列が無くなった時点で必ず終わるように直しました。削除経路ごとに解除を足すのではなく、キー処理の 1 箇所でこの不変条件を回復させているため、Backspace と同じ形の漏れがあった Delete（前方削除）も同時に直っています。

  報告手順そのもの、Delete 経路、逆の側（途中まで消した場合は英語入力を維持する）、および 4,000 打鍵の固定 seed 生成テストで検証しています。

## 対応環境

Windows 11 build 22000 以降、x64、AVX 対応 CPU。32 bit ホスト用 DLL と ARM64 ネイティブ版は含みません。

## インストール前の確認

このリリースの `sakura_setup.exe` は 1.0.0〜1.0.2 と同じくローカルビルドで、Authenticode 署名を含みません。署名の検証はできないため、ダウンロード元と SHA-256 を確認したうえでインストールしてください。署名が必要な場合は、署名証明書の secret を登録したうえで Actions の署名付きリリースワークフローを使ってください。

アップグレードは versioned payload の side-by-side 切替で行われるため、通常の終了コードは `0` で、TSF DLL が使用中でも Windows の再起動は要求されません。ロックされた旧世代は、SYSTEM のログオン時メンテナンスタスクが後で削除を再試行します。

詳細は同梱の `README-ja.md` と `guide-ja.md` を参照してください。
