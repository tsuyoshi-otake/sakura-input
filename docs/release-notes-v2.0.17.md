# Sakura Input 2.0.17

- 半角数字や「%」に続く語を変換するようにしました（#331）。これまでは「12じかん」「20けん」「50%はさける」などが、読みのまま残ることがありました。今は「12時間」のように、数字の後ろの語も漢字になります。
- IT用語の言い換え（別名）が、元の用語より先に出ないようにしました（#332）。たとえば「せっけいしょ」では「設計ドキュメント」ではなく「設計書」が先頭になります。言い換えは引き続き候補に残ります。
- 「〜てる」「〜ている」「〜てない」の形が、後ろの「ない」や助詞を取り込んで別の語になるのを防ぎました（#334）。たとえば「これであってる」は「これ出会ってる」ではなく「これで合ってる」に、「ここでずっとまってる」は「舞ってる」ではなく「待ってる」になります。
- 読みが同じ動詞（閉める/占める、降る/振る、呼ぶ/読む、空く/開く など）を、前の名詞と助詞の組み合わせから選ぶようにしました（#335）。「名詞＋助詞＋動詞」の組み合わせ230組を辞書に加えています。たとえば「まどをしめてる」は「窓を閉めてる」、「かれをよんでいる」は「彼を呼んでいる」になります。
- 同音の名詞で、よく使う表記が先頭に出なかった語を直しました（#336）。対象は、案（あん）、招待（しょうたい）、型（かた）、最終版、浮動小数点、機能フラグ、検索機能、印紙税、一時停止です。「かた」だけを変換した場合は、これまでどおり「方」が先頭です。
- 「よろしくおねがいします」「たしかに」「おまかせします」「あけましておめでとうございます」「そろそろいかないと」「おそれいりますが」で、ひらがなのままの候補が先頭に出ていました。これらは漢字の表記が先頭になるようにしました（#337）。ひらがなの表記も候補に残ります。学習の動作は変えていません。そのため、これまでひらがなで確定していた読みは、学習によってひらがなが先頭のまま残ることがあります。
- 入力途中の予測候補を整理しました（#338）。活用の途中の形（「休みゃ」など）と、日本語の語に付いた英語の言い換え（「けいやく」に対する「Contract」など）は、予測候補に出なくなります。どちらも変換候補には残ります。予測候補の枠が余るときは、入力した読みと同じ読みの語で埋めます。入力の2文字目から（これまでは3文字目から）、入力に近い短い語を長い語より先に出します。
- 予測候補では、27語が以前より出にくくなりました。26語は、予測候補の9件に入るまでに1文字多く入力する必要があります（長い語が、2文字目では短い語の後ろに回るため）。残りの1語は「おおせ」の「仰せ」で、先頭ではなくなりました。
- 2.0.16までに学習した内容は、そのまま使われます（「〜てる」の形の学習も含みます）。学習ログと設定の形式は変わりません。辞書は変わりました。

このリリースのために、変換と予測の精度を測るゲートを追加しました（#333）。ゲートは、作成した1,500文の変換と1,600語の予測で測ります。測るのは、学習・リランカー・文脈を使わない、新しいセッションでの最初の変換です。2.0.16の辞書と比べた結果は次のとおりです。先頭の候補が正解（許容する表記ゆれを含む）だった文は1,207から1,330（80.5%→88.7%）、期待した表記そのものだった文は1,142から1,265（76.1%→84.3%）に増えました。2.0.16で正解だった文のうち、悪くなった文はありません。予測では、読みをすべて入力した時点で先頭に出る語が1,171から1,239に、9件以内に出る語が1,493から1,552に増えました。9件から選べるようになるまでに省ける打鍵は、1,899から2,019（全打鍵の30.2%→32.1%）に増えました。

ほかの検証は、各Issueのテスト、配布辞書を使った変換・予測のテスト、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
