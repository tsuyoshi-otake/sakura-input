# Sakura Input 2.0.21

このリリースは、入力した読みそのままの変換候補が、誤変換の救済機能が作った候補に隠れて、候補からまったく消えてしまう問題の修正です（#385）。

- 「ふかい」と入力しても「深い」が候補に出なかったのを直しました（#385）。
  - 入力ミスを救済する仕組みが、読みを「ぶかい」と濁音に置き換えて探す候補を作ります。「ぶかい→深い」は名詞につく接尾辞の形として登録されているため変換コストが低く、本来の「ふかい→深い」より先に「深い」という表記を確保していました。
  - 同じ表記の候補は1つに絞る整理で、先に来た救済版だけが残り、あとの品質チェックが「確かでない救済由来の候補」としてそれを取り除いたため、「深い」自体が消えていました。
  - 同じ表記の候補が見つかったとき、残っている側が確かでない救済由来で、新しい側が普通の辞書由来なら、普通の辞書由来のほうを残すようにしました。
  - 同じしくみで消えていたものを調べたところ111件あり、「深い」以外に「辛い」「不足」「鈴木」「長谷川」「安藤」「藤井」などが出るようになりました。
- あわせて「きょうかいちのてすとがふそく」が「境界値のテストが不足」になるように、IT用語「境界値」の優先度を調整しました（#385）。
- 変換精度のゲートに、この問題を再現する例文7件を追加しました（合計1,537件）。

2.0.20までに学習した内容と設定は、そのまま使われます。学習で誤った候補が先頭に固定されている読みは、学習の内容がこの修正より優先されます。

検証は、変換検索の単体テスト（修正前のコードで失敗することを含む）、実際の辞書を使った候補順位の回帰テスト、変換精度のゲート（追加した例文を含む1,537件）、ワークスペース全体のテスト、リポジトリのCIゲートです。インストールしたIMEでの画面上の確認は、リリース時点では行っていません。

このインストーラーはAuthenticode未署名です。手動で導入する場合は、GitHub Releaseに掲載されたSHA-256とファイルのハッシュを照合してください。自動更新では、署名付き更新manifestを使って、サイズ・SHA-256・未署名状態を検証します。
